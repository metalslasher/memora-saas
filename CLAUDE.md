# Memora — інструкція для кожної сесії

Memora — веб-тренажер англійської для україномовних (спершу для власника,
згодом, можливо, публічний). Ядро: активне пригадування + FSRS. UI —
українською, навчальний контент — англійська з українськими перекладами.

## Звідки починати сесію
1. Прочитай `docs/roadmap.md`: розділ **«Поточний стан»** (що робимо зараз)
   і **«Журнал рішень»** (що вже вирішено, не перепитувати).
2. `git status` + `git log --oneline -5`.
3. Актуальні доки: `docs/product.md` (цільовий продукт), `docs/architecture.md`
   (поточна архітектура коду). Після змін коду/структури оновлюй architecture.md.

## Власник і стиль роботи
- Власник — користувач і валідатор, не програміст. Пиши йому українською,
  просто, без жаргону; технічні деталі — тільки коли питає.
- Інженерну організацію (архітектура, порядок, git) веде Claude самостійно.
- Сперечайся, якщо ідея слабка. Питай про продукт/стратегію, не про git.
- Якщо власник просить те, що вже робилося нещодавно (див. «Журнал
  обслуговування» в roadmap), — скажи, коли це було і чи є сенс повторювати.

## Git
- Повністю делеговано: коміти й пуші без погодження.
- `main` = прод (Vercel автодеплой). У `main` пушимо лише зелений білд.
- Пачка з кількома кроками або змінами схеми → гілка `batch-N-<slug>`;
  Vercel дає preview-URL, власник перевіряє там, потім merge у `main`.
  Увага: preview і прод ділять одну Supabase-БД.
- Дрібні правки (доки, хотфікси) — одразу в `main`.
- Коміт = одна логічна зміна; повідомлення англійською.

## Обов'язкові ритуали
| Коли | Що |

| Раз на місяць або на межі пачки, що прийшлась пізніше | оновлення залежностей, перевірка витрат AI (`ai_usage`), повний візуальний аудит — тільки якщо минуло ≥ 4 тижнів або були великі UI-зміни |
| Нова сесія | не дублювати аудит, якщо в журналі обслуговування він свіжий (< 2 тижнів) і код з того часу суттєво не мінявся |

## Стек і команди
- Next.js 16 App Router, React 19, TypeScript, Tailwind v4, Supabase (Auth +
  Postgres + RLS), `ts-fsrs`, Vitest, Playwright. Хостинг Vercel (Hobby),
  Supabase Free (засинає після ~7 днів без запитів).
- Supabase project id: `whqfpktgwwctqhqvsoqm` (див. розділ «Supabase і Vercel»).
- Залежності ставити через `npx pnpm@11.7.0 …` (глобально стоїть pnpm 9).
- Команди: `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`, `pnpm smoke`, `pnpm test-user`.
  Локальний dev: `pnpm dev` (у `pnpm-workspace.yaml` має бути `packages: ["."]`,
  інакше pnpm 9 падає з «packages field missing»). Тестовий акаунт:
  `pnpm test-user`; smoke: `pnpm smoke` (див. docs/architecture.md).
  Справжній пуш: `node --env-file=.env.local scripts/push-check.mjs` (після `pnpm test-user`, на `pnpm start`; відкриває вікно Chrome).
  Нагадування: Vercel env `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `CRON_SECRET`; щогодини маршрут `/api/cron/reminders`
  викликає Supabase `pg_cron` (секрет у Vault `cron_secret`).
  AI-скрипти (TS): `npx tsx --env-file=.env.local scripts/ai-compare.ts` (тексти),
  `scripts/tts-compare.ts` (голоси) — платні, пишуть в `ai_usage`.
  Програма: `npx tsx --env-file=.env.local scripts/import-lexicon.ts` — ідемпотентний імпорт
  `data/lexicon/*` у `lexicon` (запускати після змін списків); `scripts/build-program.ts` —
  разова платна генерація тематичних добірок і пулу тесту (результат вичитати вручну).
- Секрети тільки в `.env.local` (gitignored) і Vercel env. Ніколи в git/чат.
- AI-ключі (OpenAI, Google) — тільки на сервері. Жорсткий ліміт витрат
  $10/міс на весь проєкт.

## Принципи продукту (не порушувати)
- Відповідь не показується до спроби пригадати.
- Одне слово — не більше однієї картки на день (sibling burying).
- Кожна платна AI-фіча має оцінку вартості і облік у БД.
- Без «повітря» в UI: щільно, сегментовано, mobile-first (Android — основний пристрій власника).
- Лендінг і довідка описують тільки те, що реально працює.
- **Якість мови.** Англійська — природна американська, як говорять носії
  (без «підручникових» конструкцій). Українська — жива, звична більшості,
  без кальок і канцеляриту. Стосується UI, лендінгу, довідки, AI-промптів,
  стартового контенту.
- **Видалення = повне видалення.** Прибрали фічу → прибрати код, тести,
  таблиці/колонки, тексти, налаштування. Без мертвого коду.
- **Рішення в навчанні спираються на дослідження/кращі практики** — якщо їх
  нема, позначати як експеримент.

## Виконання пачок (з 2026-11-19)
- **Головний чат** — обговорення, рев'ю, merge, оновлення roadmap.
- **Кожна пачка — вкладений чат під головним.** Головний чат пише ТЗ у
  `docs/batches/batch-N.md`, пушить його і створює чат через
  `mcp__claude-code-remote__create_session` (модель і effort — з таблиці в roadmap,
  title «Memora · пачка N — <суть>», prompt: «Виконай docs/batches/batch-N.md»
  + абсолютний шлях до репо). Чат працює на ПК власника (Remote Control), бачить
  `.env.local`, а власник бачить у ньому всі запити. Стан перевіряти через
  `get_session` / `list_events`. **Фонові агенти (Agent tool) для пачок не
  використовувати** — вони не можуть показати запит на дозвіл і зависають.
- Чат пачки працює в гілці `batch-N-<slug>`, у кінці пушить її і пише короткий
  звіт. Merge у `main` робить головний чат після рев'ю.

## Supabase і Vercel
- Міграції: MCP `apply_migration` зависає на невидимому підтвердженні — не
  використовувати. Робочий шлях — CLI (залогінений, проєкт прив'язаний):
  `supabase db query --linked -f <file.sql>` (усе в `begin; … commit;`) +
  `insert into supabase_migrations.schema_migrations (version, name) …`;
  файл — `supabase/migrations/<version>_<name>.sql`. Потім advisors і
  `supabase gen types typescript --linked > src/lib/supabase/database.types.ts`.
  Читання (list_tables, advisors, execute_sql select) через MCP — ок.
- Перед будь-яким `drop` функції/таблиці/колонки — перевір залежності в самій БД
  (тіла функцій через `pg_get_functiondef`, в'ю), а не лише grep по файлах: 2026-11-26
  cleanup пачки 7 видалив `get_streak`, а `get_progress_stats` її ще викликав — «Прогрес» на проді падав.
- Vercel MCP: team `metalslashers-projects` (`team_fxQ3xAZ8zn9jn0C9dPrtBgwJ`),
  project `memora-saas`; доступ авторизовано. При 403 — `authorize_team_access`
  і дати власнику лінк. Запасний шлях: `gh api repos/metalslasher/memora-saas/commits/<ref>/status`.
