# Memora — аудит і план перезбірки

Робочий документ підготовчого раунду. Тут живуть: висновки аудиту, рішення,
відкриті питання й пачки задач. Оновлюється після кожної ітерації обговорення
і після кожної виконаної пачки.

Статус: **раунд 1 — обговорення** (2026-11-19). До коду не переходимо, поки
не закриті питання з розділу 6.

---

## 1. Ціль

Memora — особистий тренажер англійської, яким реально користуєшся щодня з
телефона й ПК. Ядро — активне пригадування + FSRS. Усе, що не підсилює
вивчення англійської, прибираємо. QA-модуль видаляємо повністю.

Критерії «готово»:
- щоденна сесія 10–15 хв без тертя (відкрив → пройшов → закрив);
- додати нове слово можна за ~5 секунд, з будь-якого місця;
- кожне слово тренується в кількох напрямках (впізнати, згадати, вжити, почути);
- інтерфейс щільний, без «повітря», однаково добрий на 375px і на 1440px;
- без багів, без лагів, безпечно, витрати на API — копійки на місяць.

## 2. Аудит: що є зараз

### 2.1 Стек і інфраструктура
- Next.js 16 (App Router) + React 19 + TypeScript + Tailwind v4, Vercel,
  Supabase (Auth + Postgres, RLS), `ts-fsrs` 5.4.1.
- Supabase-проєкт `Memora` (eu-west-1) — **ACTIVE_HEALTHY** після відновлення.
  Free-план ставить проєкт на паузу після ~7 днів без запитів. Саме через це
  він і заснув.
- Даних майже немає: 2 користувачі, 13 нотаток (12 стартових), 18 карток,
  8 повторень за 2 дні. **Схему можна міняти радикально, без міграції даних.**

### 2.2 Архітектура: проблеми
| # | Проблема | Наслідок |
|---|---|---|
| A1 | Увесь кабінет живе на одному URL `/`, екрани перемикає `useState` | Не працює «назад» на Android, після refresh губиться екран, немає deep-link |
| A2 | `loadRemoteMemoraState` тягне **всі** нотатки, картки й **усі review_logs** при кожному завантаженні | Через рік щоденної практики це десятки тисяч рядків на кожен вхід |
| A3 | Більшість мутацій (нотатки, CSV, налаштування) повертає й перезавантажує весь стан | Повільно, зайвий трафік |
| A4 | `memora-app.tsx` (931 рядок) — оркестратор усього: auth, стан, практика, undo, тости | Важко змінювати, легко зламати |
| A5 | Мертвий код: localStorage-стор у `store.ts`, `reviewCardAction`, `suspendCardAction`, `seed.ts`; невикористані таблиці `tags`, `note_tags`, `media`, `analytics_daily` | Шум для майбутніх сесій |
| A6 | Історія міграцій Supabase розходиться з локальною (див. `current-implementation.md`) | Не можна безпечно робити `db push` |
| A7 | `pnpm dev` не запускається: `pnpm-workspace.yaml` без поля `packages` | Ламає локальну розробку |
| A8 | Немає `CLAUDE.md`, документація — 7 файлів зі старої PDF-специфікації (Redis, QA, ISTQB тощо) | Кожна нова сесія збиватиметься на застарілий контекст |

### 2.3 Логіка навчання: проблеми
| # | Проблема | Наслідок |
|---|---|---|
| L1 | Слово = 2 картки (uk→en і en→uk) із шаблонним промптом «Як сказати англійською: …?» | Мало контексту, слово вчиться як пара перекладів, а не як вживання |
| L2 | Немає «sibling burying»: обидві картки одного слова можуть вийти в той самий день одна за одною | Друга картка підказує відповідь на першу, і пригадування не відбувається |
| L3 | Ліміт нових рахує **картки**, а не слова | 10 нових/день = насправді 5 слів |
| L4 | Перевірка відповіді: Левенштейн + коми/слеші. Синонімів і словоформ немає | Правильний синонім = «Не згадав». Лендінг при цьому обіцяє «синоніми — не проблема» |
| L5 | Немає карток на аудіювання, контекст (cloze), вживання в реченні | Пасивний словник росте, активний — ні |
| L6 | FSRS: стандартні параметри, `enable_fuzz: false`, без персональної оптимізації; доступний `ts-fsrs` 6 | Інтервали не підлаштовуються під тебе, картки злипаються в «хвилі» |
| L7 | «Важкі» картки (leech, 4+ провали) тільки показуються в прогресі, сценарію «виправити» немає | Зависають і з'їдають час |
| L8 | Вимова — Web Speech API; якість голосу залежить від пристрою (на Windows/Android буває роботизована) | Слабке аудіо = погане аудіювання |
| L9 | Додавання слова вручну: лема, переклад, приклад — усе руками | Найбільший бар'єр щоденного використання |

### 2.4 UI / дизайн
- **Баг фліп-картки в hero (підтверджено скрінами):** у `CardStack` анімована
  картка і дві картки стосу позаду в одному `preserve-3d` контексті. Під час
  повороту вона геометрично «розрізає» їх. Плюс контент міняється на наступну
  картку в момент, коли та ще повертається. Тому видно половину старої і
  половину нової. Фікс: ізолювати 3D-шар, обертати завжди вперед (+180°) і
  міняти контент тільки на невидимій грані.
- Лендінг довгий: ~8600px на десктопі, ~10000px на телефоні. Блок
  «Три кроки» на десктопі займає 3 екрани з напівпорожньою правою частиною.
  Плитки бенто на телефоні високі й порожні; плитка «клавіатурні скорочення»
  на телефоні не має сенсу.
- Копірайт обіцяє те, чого немає («синоніми»), і досі розповідає про QA.
- Кабінет я візуально ще не бачив (потрібен тестовий акаунт, див. питання 6.10).
  З коду видно: 5 вкладок (Практика / Слова / QA / Прогрес / Профіль), діалоги,
  тости, heatmap. Після прибирання QA навігація стане 4-вкладковою.

### 2.5 Безпека
- RLS на всіх таблицях ✔; RPC-функції `security invoker` із `search_path` ✔;
  мутації через server actions із валідацією ✔.
- Advisor: **Leaked Password Protection вимкнено** (дія з твого боку, якщо
  доступно на плані).
- Немає security headers (CSP, `X-Frame-Options`, `Referrer-Policy`) у `next.config.ts`.
- Немає rate-limit. Поки AI немає, це не критично. З AI стане обов'язковим
  (бюджетний ліміт на користувача).
- Реєстрація відкрита всім. Якщо сервіс особистий, її варто закрити (див. 6.6).

## 3. Пропоноване бачення продукту

### 3.1 Модель слова (замість 2 шаблонних карток)
Одна **нотатка-слово** зберігає: лему, значення (uk), частину мови, IPA,
2–3 приклади, колокації, типові помилки, рівень CEFR, теги, джерело (де
зустрів). З неї генеруються картки різних типів:

| Тип картки | Що тренує | Як виглядає |
|---|---|---|
| Recognition (en→uk) | впізнавання | бачиш слово/фразу в реченні → згадуєш значення |
| Recall (uk→en) | активне пригадування | бачиш значення + підказку з контексту → пишеш слово |
| Cloze | вживання в контексті | речення з пропуском → вписуєш слово в правильній формі |
| Listening | аудіювання | чуєш слово/речення → пишеш, що почув |
| Use it (AI, опційно) | продукування | пишеш власне речення → AI дає короткий фідбек |

Нові слова спершу йдуть як Recognition. Recall, Cloze і Listening
відкриваються поступово, коли слово «дозріло». Плюс sibling burying: одне
слово — максимум одна картка на день.

### 3.2 Захоплення слів (головний важіль щоденного використання)
- **Швидке додавання:** вписав `slip` → AI заповнює все інше → підтвердив.
- **Вставка списку / тексту:** вставив абзац зі статті чи субтитрів → обрав
  незнайомі слова → вони збагачуються пачкою.
- **Share target (Android PWA):** «Поділитися → Memora» з будь-якого застосунку.
  На iOS так не можна, там лишається тільки вставка.
- **Стартові колоди за рівнем:** частотні списки (кандидат — NGSL / NAWL /
  BSL, ліцензія CC BY-SA; перевіримо перед використанням). Обираєш рівень і
  тему, AI збагачує слова ліниво, по мірі потреби.

### 3.3 Практика
- Одна кнопка «Почати» → черга на сьогодні; вибір довжини сесії (5 / 10 / 20 хв).
- Типінг обов'язковий для Recall/Cloze/Listening. Для Recognition можна відповідати подумки.
- Розумніша перевірка: прийнятні варіанти й синоніми (з AI-збагачення),
  словоформи (`slip/slips/slipped`), а при помилці — підсвітка різниці.
- Leech-флоу: після 4 провалів картка пропонує «переписати / додати приклад /
  розділити / пауза».
- FSRS 6 + fuzz; персональна оптимізація параметрів, коли назбирається
  ~400+ повторень (оптимізатор `@open-spaced-repetition/binding`, запускається
  на сервері або вручну з налаштувань).

### 3.4 Звичка
- Web push-нагадування (iOS 16.4+ тільки для встановленої PWA; Android —
  повноцінно) через Vercel Cron 1×/день. Альтернатива — Telegram-бот
  (див. 6.3).
- Денна ціль, серія з «заморозкою» (1 пропуск на тиждень не скидає серію).
- Побічний ефект: щоденні запити не дадуть Supabase заснути.

### 3.5 AI: що варто, а що ні
| Фіча | Користь | Модель | Оцінка вартості/міс* |
|---|---|---|---|
| Збагачення слова (переклад, IPA, приклади, колокації, cloze, синоніми, типові помилки) | Дуже висока | gpt-5-mini або gpt-5-nano | ~$0.20–1.20 при 600 словах/міс |
| Фідбек на власне речення (Use it) | Висока | gpt-5-mini | ~$0.50 при 30 реченнях/день |
| Якісне аудіо (TTS) з кешем у Supabase Storage | Середня/висока | OpenAI TTS або Gemini TTS | ~$0.50–1 (кожне слово озвучується один раз) |
| Розмовна практика / вимова (запис → транскрипція → фідбек) | Висока, але дорожча й складніша | gpt-4o-mini-transcribe + gpt-5-mini | ~$1–2 при 10 хв/день |
| Картинки до слів (fal.ai) | Низька для дорослого рівня | — | не рекомендую |
| Відео (fal.ai) | Немає | — | не рекомендую |

\*Ціни з агрегаторів станом на листопад 2026: gpt-5-mini — $0.25 вх / $2 вих
за 1M токенів, gpt-5-nano — $0.05 / $0.40, transcribe-mini — ~$0.003/хв.
Перед реалізацією звіримо з офіційною сторінкою. **Реалістичний підсумок:
$2–4/міс з усім увімкненим, <$1 тільки зі збагаченням.** Додамо жорсткий
місячний ліміт витрат у БД, щоб сюрпризів не було.

## 4. Технічні рішення (пропозиція)
- **Маршрути:** `/` (лендінг), `/app` (сьогодні), `/app/practice`, `/app/words`,
  `/app/words/[id]`, `/app/progress`, `/app/settings`. Серверний рендер даних
  сторінки, клієнтський стан тільки для практики.
- **Дані:** черга на сьогодні рахується запитом/RPC у БД, статистика —
  агрегатами в SQL, а не з повного масиву логів на клієнті.
- **Схема v2:** чиста міграція (дані скидаємо, лишаються тільки
  `auth.users`): `profiles`, `words`, `cards`, `review_logs`, `ai_usage`,
  `audio_cache`, `push_subscriptions`. Без deck/QA-енумів.
- **AI:** тільки на сервері (Route Handler / server action), ключі у Vercel
  env, вихід через structured output (JSON-схема), облік токенів в `ai_usage`.
- **Міграції:** відновити синхронну історію або почати з однієї baseline-міграції.
- **Якість:** Vitest для логіки, Playwright e2e (авторизований smoke) у CI,
  security headers, перевірка a11y.

## 6. Відкриті питання до тебе

1. **Рівень і ціль.** Який у тебе зараз рівень (A2 / B1 / B2 / C1) і навіщо
   англійська в першу чергу: робота в IT (мітинги, листування), розмовна,
   читання/серіали, переїзд, іспит? Від цього залежать стартові колоди й типи карток.
2. **Звідки беруться нові слова?** Серіали, робота, статті, книги, ігри?
   Від цього залежить, який спосіб захоплення робимо першим.
3. **Телефон: iPhone чи Android?** Push і share target працюють по-різному.
   І чи цікавий тобі Telegram-бот для нагадувань і швидкого додавання слів
   замість/поряд із push?
4. **Мова інтерфейсу.** Лишаємо UI українською (контент англійський), чи
   переводимо UI на англійську для занурення? Моя рекомендація — українська
   зараз, перемикач згодом.
5. **Час на день**, який реально готовий виділяти: 5, 10, 20 хв?
6. **Особистий інструмент чи публічний SaaS?** Якщо тільки для тебе,
   закриваємо реєстрацію, лендінг стає візиткою, і не треба думати про
   мультитенантні ліміти. Якщо колись публічний, закладаємо це зараз.
7. **Поточні дані** (13 нотаток, 8 повторень) — ок стерти й почати з чистої схеми v2?
8. **AI-бюджет:** стеля на місяць (пропоную $5 як жорсткий ліміт) і
   провайдер (пропоную OpenAI, ключ уже є; Gemini як запасний)?
9. **Розмовна практика / вимова** з мікрофоном — хочеш у першій хвилі чи пізніше?
10. **Доступ для аудиту кабінету й e2e-тестів.** Варіант А: ти реєструєш
    тестовий акаунт і даєш мені логін/пароль у `.env.local`. Варіант Б: кладеш
    `SUPABASE_SERVICE_ROLE_KEY` у `.env.local` (у git він не потрапить), і я
    сам створюю тестових користувачів і запускаю smoke.

### Дії з твого боку (коли буде зручно)
- Supabase → Authentication → увімкнути **Leaked Password Protection** (якщо доступно на плані).
- Підтвердити, що на Vercel підключений саме цей репозиторій і гілка `main`
  (я ще перевірю через Vercel-інтеграцію).
- API-ключі OpenAI (і, за бажання, Google) знадобляться лише на пачці 3.
  Їх треба буде додати у Vercel → Project → Environment Variables, у чат не скидай.
