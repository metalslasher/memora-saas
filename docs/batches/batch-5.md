## Мета
Кабінет виглядає як цілісний якісний застосунок на Android-телефоні: щільно, без
«повітря», без дублювання, з однією візуальною мовою на всіх екранах — і ставиться на
головний екран як застосунок, з «Поділитися → Memora» з будь-якої програми.

## Задачі
1. **Візуальний прохід усіх екранів кабінету** (`/app`, практика всіх типів вправ,
   слова + картка слова, додавання/«З тексту», прогрес, налаштування, онбординг, довідка,
   вхід) на 375 / 768 / 1440. Закрий пункти аудиту §2.4, які ще актуальні. Одна система:
   відступи, типографіка, кольори-токени, стани (порожньо / завантаження / помилка),
   фокус і тап-цілі ≥ 44 px. Нове замінює старе — без паралельних варіантів і мертвих
   стилів. Логіку практики не чіпай (крім виправлення явних багів, які знайдеш).
2. **Анімації — стримано:** переходи карток і показ відповіді, без затримки дій;
   `prefers-reduced-motion` поважати.
3. **Вичитка всіх текстів UI і довідки** (рішення з журналу: вичитка в пачках 5 і 8):
   жива українська без кальок і канцеляриту, природна американська англійська; без
   службових/технічних написів для користувача; помилки — людською мовою (що сталось і що робити).
4. **PWA:** `manifest` (назва, іконки всіх потрібних розмірів включно з maskable, тема,
   `display: standalone`, `start_url: /app`), мінімальний service worker (без офлайн-режиму —
   він «пізніше»; але так, щоб пачка 7 могла додати web push), підказка «Встановити» у
   доречному місці, не нав'язливо.
5. **Share target (Android):** «Поділитися → Memora» приймає текст/посилання:
   одне слово або коротка фраза → форма «Додати слово» з заповненим полем; довший текст →
   «З тексту». Неавторизований користувач — після входу повертається туди ж.
6. **Повний візуальний аудит «після»:** знімки тих самих екранів, що в §2.4 «до», у
   `C:\tmp\memora-shots\batch5\` (375 / 768 / 1440); коротке порівняння «до → після» в
   roadmap §2.4 або журналі обслуговування.
